# ygo-cardid-tool（卡密工具）

使用 Python 和 Tkinter 编写的 Windows 桌面工具，用于生成、检查卡片密码（`datas.id`），以及检索和登记系列码（`datas.setcode` / `strings.conf` 的 `!setname`）。两类代码是不同的字段：**生成卡密不会修改系列码，登记系列码也不会修改卡库中的卡片。**

## 启动

- 从源码运行：在本目录执行 `python cardid_tool.py`。需要带 Tkinter 的 Python；其他依赖均为标准库。
- 也可按下文说明自行打包，运行 `dist/卡密工具.exe`。打包产物未上传到仓库。

界面有「随机生成」「检测卡密」「卡库」「系列码检索」四页。第一次使用建议先在「卡库」页载入需要参与查重的 `.cdb` 文件或文件夹；选择文件夹时会递归扫描其中的 `.cdb`。

## 卡密：生成与检测

1. 在「卡库」页选择 `.cdb`，点击「保存记忆」。卡库只用于读取已有 `datas.id` 和 `datas.setcode`，工具不会改写它。
2. 在「随机生成」页设置起始、结束和数量。默认卡密范围是 **900000000–900099998**（含两端）。勾选「避开已存在卡密（查重）」时，会避开已载入卡库中的卡密以及本次已生成的卡密；可复制结果或导出 TXT/CSV。
3. 在「检测卡密」页输入一个或多个数字，以换行、空格或逗号分隔。工具按当前生成范围和已载入卡库标记类型、重复状态，并可导出结果。

如果卡库文件后来发生变化，在「卡库」页点击「刷新」，再生成或检测。没有载入卡库时，卡密检测只能判断输入和范围，无法判断是否与游戏卡库重复。

## 系列码：检索、生成与写入

「系列码检索」页支持中文名称、十进制和 `0x` 十六进制检索。例如 `妖精传姬`、`475` 和 `0x1DB` 指向同一个系列码。选中结果后可以复制十进制或十六进制代码。

新增系列码时：

1. 确认页面显示的名称来源是要修改的游戏 `zh-CN/strings.conf`。本机默认路径为 `D:\Game\MDPro3\Data\locales\zh-CN\strings.conf`；其他位置可点「读取 strings.conf」选择，路径会记住。
2. 点「随机生成未用码」，或在「系列码」框输入十进制 / `0x` 代码后点「检测重复」。有效范围是 **1–65535**（`0x1–0xFFFF`）。查重会对比当前 `strings.conf` 的 `!setname` 和**已载入卡库**实际使用的四段 16 位系列码。
3. 输入中文名称，点「写入 strings.conf」。工具会再次读取目标文件并检查代码是否已登记；成功后在最后一条 `!setname` 后插入新条目，并刷新检索结果。

写入前会在配置文件旁创建备份，文件名从 `strings.conf.bak` 开始；已有备份时依次使用 `.bak1`、`.bak2` 等。工具保留原文件的 UTF-8 BOM（如果有）和换行格式。若文件在写入期间被其他程序修改，写入会停止。

**查重范围以已载入的卡库为准。** 若还有其他游戏卡库，先在「卡库」页载入并刷新。写入 `strings.conf` 只登记名称；要让卡片使用新系列码，仍需在卡片编辑器里设置该卡的 `setcode`。

## 名称来源与同步

`setnames.json` 是可选的内置中文名称快照，由游戏配置中的 `!setname` 条目生成，不随公开源码提供。缺少它时程序从空名称表启动；可在界面中点「读取 strings.conf」载入名称。同一行若还用制表符附有日文名，只取制表符前的中文名称。运行时选择 `strings.conf` 后会载入该文件；生成和检测时还会重新读取，以发现外部更新。若只需刷新检索列表，可再点一次「读取 strings.conf」。点击「恢复内置名称」会改回快照；要继续写入游戏配置，需重新选择 `strings.conf`。

游戏配置更新后，如需更新源码快照，在本目录执行：

```powershell
python gen_setnames.py "D:\Game\MDPro3\Data\locales\zh-CN\strings.conf"
```

这个命令只更新本项目的 `setnames.json`，它会被 Git 忽略。安卓编辑器有独立的名称表；如需同步安卓端，参见 [安卓打包指南](https://github.com/FORSTNOVA/ygo-cdb-editor/blob/main/BUILD.md)。

## 打包

安装 PyInstaller 后，在本目录执行：

```powershell
pyinstaller --noconfirm "卡密工具.spec"
```

输出在 `dist/卡密工具.exe`。若本地已生成 `setnames.json`，`卡密工具.spec` 会将它打进单文件程序；否则程序启动时使用空名称表，可在界面里选择游戏配置。`CardIdTool.spec` 是英文文件名的另一份打包配置。两份 spec 均使用项目内的相对路径。

源码还提供 `python cardid_tool.py --selftest`，用于运行卡密核心逻辑的内置自检。

## 文件说明

| 文件或目录 | 用途 |
| --- | --- |
| `cardid_tool.py` | 卡密与系列码逻辑、Tkinter 界面 |
| `gen_setnames.py` | 解析游戏 `strings.conf`，生成内置名称快照 |
| `setnames.json` | 本机生成的系列码中文名称快照，不上传仓库 |
| `卡密工具.spec` / `CardIdTool.spec` | PyInstaller 打包配置 |
| `dist/`、`build/` | 打包产物和中间文件 |
| `cardid_config.json` | 用户记忆的卡库、生成范围和 `strings.conf` 路径；源码运行时位于脚本旁，打包运行时位于 exe 旁 |

`cardid_config.json` 是运行时的用户配置，不是内置名称表。复制或更新 exe 时，保留它即可延续原来的卡库和路径设置。
